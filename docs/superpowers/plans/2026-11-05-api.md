# Go API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 12 APIをGoで実装し、Firebase・Firestore・Maps・Geminiへ接続する。

**Architecture:** 標準HTTPのルーターから既存のAPIパッケージへ接続する。共有型・保存・外部接続・計算はinternal/serviceに置き、外部SDKとHTTP境界をテストで差し替える。

**Tech Stack:** Go 1.26、net/http、Firebase Admin Go SDK、Firestore Go SDK、Maps/Gemini REST。

**Spec:** ../specs/2026-11-05-api-design.md（利用者承認済み）

## Global Constraints

- /healthz以外はFirebase ID tokenが必須。他人の旅程・案は404。
- qは1〜100文字、textは200文字以内、placesは1〜10件、stayMinは10〜480分、delayMinは0〜600分。
- #2・#3・#6・#7・#10と#8の理由文にAIを使う。#10はGET。
- If-Matchとトランザクションで更新競合を防ぐ。期限は旅程30日、案15分。
- キーは環境変数。認証スキップ・実データ投入・デプロイ・pushはしない。

## Review Focus

- 別uid、期限切れ、誤ったIf-Matchで他人のデータや古い案を保存しない（Task 2/4）。
- AIが未知の施設・重複した施設を返しても保存しない（Task 3）。
- 営業時間の複数区間、閉店日、日付境界と待ち時間を正しく検証する（Task 3）。
- 遅延した現在の予定と完了済みの予定を組み直しで失わない（Task 4）。
- 不正JSON、上流429、キャンセル、理由文の生成失敗をHTTPの契約どおり扱う（Task 1/4/5）。
